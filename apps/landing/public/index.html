A day with Standwise

Set two times in standwise.yml. Standwise runs the rest.

This team has remind_at: "09:30" and digest_at: "10:00" in São Paulo time, Monday to Friday.

  1. Draft08:50

    Ana runs /daily. She edits the draft, adds a blocker that links a pull request and confirms. The reviewer gets a direct message.

  2. remind_at09:30

    Davi hasn't written yet, so he gets one reminder. Never more than one a day.

  3. digest_at10:00

    One digest per team in #daily-backend: blockers first, then updates, then who hasn't sent.

  4. Late10:40

    Davi sends late. His daily goes in the digest thread, so nobody misses it.

What it does

Collects, consolidates and delivers. You only write.

A draft from real work

Pull requests opened, merged and reviewed, commits by repository, and Linear cards that started or finished. Monday covers the weekend.

Blockers reach who can help

A blocker that links a pull request goes to its reviewers, then CODEOWNERS, then the team managers. A Linear card goes to the owner of the blocking card.

Nothing sent without you

The MCP submit tool needs confirmed: true, which the agent passes only after you approve the text.

Several teams, one daily

Write once and appear in every team digest you belong to, each in its own time zone and workdays.

Managers read from their agent

Team digests, dailies and blockers for the last 90 days, through MCP read tools. Confirmed content only.

API and webhooks

Read-only API keys with scopes, an OpenAPI reference, and signed daily.submitted and blocker.opened webhooks.

Privacy

Built for teams, not for watching people.

Standwise suggests blockers from your own signals. Those suggestions belong to you. A test in CI checks that they never leave your draft.

Your team sees

  • Dailies you confirmed, in the team digest
  • Blockers you confirmed, routed to who can help
  • Who hasn't sent today's daily

Only you see

  • A pull request waiting days for review
  • CI failing on your branch for a day
  • A Linear card stuck in progress

No productivity metrics. No rankings. No commit counts. Nothing sent on anyone's behalf.

Configuration as code

One file in your .github repository.

Teams, times, Slack channels and managers live in standwise.yml. Every change is reviewed like code.

  • Checked on every push. A Standwise config check run points to the line with the error.
  • Never breaks the team. An invalid push keeps the last valid config in effect.
  • Teams from GitHub. Members can be logins or @org/team.
# .github/standwise.yml
teams:
  - name: Backend
    timezone: America/Sao_Paulo
    workdays: [mon, tue, wed, thu, fri]
    remind_at: "09:30"
    digest_at: "10:00"
    chat:
      provider: slack
      channel: "#daily-backend"
    tracker:
      provider: linear
      team: BE
    managers: [bruno]
    members: ["@acme/backend"]
✓ Standwise config passed · 1 team, 6 members

FAQ

Questions before you install.

Is it free?

Yes, during the public beta.

Does Standwise read our code?

No. The GitHub App reads pull requests, reviews, checks, commit metadata, standwise.yml and CODEOWNERS. It never reads source files.

What do I need?

A GitHub organization or personal account and a Slack workspace. Linear is optional. Google Chat and Jira are in development.

Can my manager see my suggested blockers?

No. Suggestions are visible only to you, in your own draft. They never reach the digest, the API, webhooks or managers.

Can we self-host?

Yes. Standwise is MIT licensed. The self-hosting section of the README covers the API, the worker and Postgres.
